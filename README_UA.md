# OpenFO Local Build Kit — Windows x64

Цей комплект дозволяє **локально скомпілювати OpenFO з вихідного коду** для порівняння базового D3D9Ex з оптимізованим. Це **не** готова виправлена гра: причину регресії `PresentEx`/`ResetEx` потрібно встановити на реальному ПК. У комплекті немає оригінальних ресурсів FlatOut.

## Швидкий запуск (Windows 10/11 x64)

1. Розпакуй ZIP, бажано в `C:\OpenFO-Build` (короткий шлях латиницею).
2. Двічі клацни **`INSTALL_BUILD_TOOLS.cmd`**, якщо не встановлено CMake і Ninja. Установка використовує Windows Package Manager (winget). Після неї відкрий нове вікно термінала. Якщо winget немає, встанови CMake і Ninja вручну.
3. Запусти **`BUILD_LOCAL.cmd`**. Скрипт автоматично завантажить перевірений за SHA256 Zig 0.14.1, а також зафіксовані версії бібліотек із GitHub, після чого запустить CMake/Ninja.
4. Результат шукай у **`output\optimized_093\`**: `OpenFO.exe`, `OpenFO_D3D9.exe`, `OpenFO_Diagnostics_OpenGL.exe`, `OpenFO_Diagnostics_D3D9.exe`, `OpenFOValidate.exe`.
5. Для перевірки регресії додатково запусти **`BUILD_BASELINE.cmd`**. Отримаєш `output\baseline_084\`. `BUILD_BOTH.cmd` збирає обидві гілки послідовно.
6. Копіюй EXE **у копію своєї папки гри з оригінальною `data\`**, а не поверх робочого встановлення. Для коректного порівняння тестуй обидві збірки в однакових умовах: та сама траса, роздільність, масштаб рендеру, VSync, ліміт FPS.

> Під час першого запуску потрібен інтернет. Сторонні бібліотеки не включені повністю в ZIP, а завантажуються скриптом, оскільки попередні архіви OpenFO їх не містили. Під час наступних збірок файли лишаються в `.downloads\` та `source\...\vendor\`.

## Які гілки наявні

- **baseline_084** — реконструйований повний вихідний код 0.8.4, без патчів оптимізації 0.8.5–0.9.0. Служить для A/B-тесту продуктивності й D3D9Ex.
- **optimized_093** — вихідний код 0.9.0 (із змінами 0.8.5–0.9.0) + сумісний патч інтеграції `camera.ini` 0.9.3. Це **реконструкція з доступних архівів**, а не гарантовано точна копія EXE 0.9.3, який зараз запущено на твоєму ПК. Виправлень `PresentEx`/`ResetEx` тут поки немає.

Сервер Google Cloud 0.9.4 оновлюється незалежно; локальний комплект призначений насамперед для клієнтського EXE. Адреса майстерсервера для компіляції — `34.118.26.31:27267`, її можна змінити параметром `-MasterServer`.

## Вибір режиму з PowerShell

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\build-local.ps1 -Variant optimized_093 -Configuration RelWithDebInfo -Toolchain zig -Jobs 2 -RunTests
```

Для власної Visual Studio 2022 із компонентом **Desktop development with C++**:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\build-local.ps1 -Variant optimized_093 -Configuration Release -Toolchain msvc -Jobs 2 -RunTests
```

`-Jobs 2` спеціально обмежує паралельне складання, щоб не перевантажувати старі ПК. Для 16 ГБ RAM можна спробувати `-Jobs 4`.

## Що завантажується автоматично

- Bullet Physics **3.25**, вихідні файли `src/`.
- meshoptimizer **v0.25**, включно з `simplifier.cpp`, `allocator.cpp` та `meshoptimizer.h`. Потрібний API `meshopt_SimplifyPermissive`.
- stb_vorbis із зафіксованого коміту `9f755b604db3492df2cbeb39bf84b81e3e3932e3` у вигляді `vendor/stb_vorbis.cpp`.
- nlohmann/json **3.11.3**, вже включено як `vendor/nlohmann/json.hpp` із попереднього пакета майстерсервера.
- Zig **0.14.1**, точний SHA-256 архіву перевіряється скриптом перед розпакуванням.

Залежності завантажуються лише з офіційних джерел. ZIP-архіви бібліотек прив'язані до тегів, але **не мають попередньо зафіксованих SHA256 у комплекті**; скрипт записує їх під час отримання. Для корпоративного/offline build краще попередньо підготувати та перевірити кеш.

## Перевірки та помилки

- `output\optimized_093\build.log` — повний журнал конфігурації й компіляції; окремий файл для baseline.
- `SHA256SUMS.txt` — контрольні суми локально зібраних EXE.
- Якщо є помилки `btBulletDynamicsCommon.h` або `meshoptimizer.h` — перевір `vendor` і доступність GitHub.
- Якщо `cmake` або `ninja` не знайдено — встанови через `INSTALL_BUILD_TOOLS.cmd`, після чого відкрий **новий** термінал.
- Якщо `D3D9Ex` не запускається, перевір `OpenFO_Diagnostics_D3D9.exe` та надішли `build.log` + діагностичний ZIP. До встановлення причини не треба відключати `ResetEx` навмання.
- У разі помилок компіляції на MSVC користуйся зафіксованим Zig 0.14.1, бо попередні EXE OpenFO збиралися саме на ньому.

## Регресійний тест продуктивності

1. Збери `baseline_084` і `optimized_093` у `Release`.
2. Зроби окремі копії папки гри, поклади відповідні EXE та збережи однакові ресурси `data\`.
3. Вимкни VSync, постав однакове обмеження FPS, однакову роздільність і масштаб 100%.
4. Пройди одну і ту саму трасу (зокрема `racing1`) з однією камерою, однаковим числом ботів і налаштуваннями графіки.
5. Порівняй `FPS avg / 1% low / frametime P95/P99` і лог `PresentEx`, `ResetEx`, компіляції шейдерів та `cluster_culling`. Нульове значення `successful_presents` у старому звіті може бути помилкою лічильника — його треба звіряти з фактично видимими кадрами.

## Обмеження перевірки комплекту

Побудовано та звірено дерево вихідних файлів, перевірено застосування патчів 0.8.4 і 0.9.3, а також статично перевірено CMake-залежності й цілі. **Windows-компіляцію та запуск EXE в цьому середовищі не виконано**; скачування бібліотек і роботу Zig/CMake/Ninja необхідно перевірити на Windows. Якщо виникне помилка, журнал дасть змогу виправити саме локальний pipeline, не втрачаючи код.
