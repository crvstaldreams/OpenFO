# Frontend port to Direct3D9Ex

Source ancestry: `legacy040/ARGN_Engine_CPP/src` v0.23:

- `race_menu.hpp/.cpp` → `frontend.hpp/.cpp`: the menu state machine, authored selections, profile, cash/upgrade ownership, control rebinding, track grid, keyboard/mouse navigation and explicit unsupported mode messages.
- `race_menu_gl.cpp` → `frontend_draw.cpp`: source 640×480 placement, original atlases, original eight ABC font faces, dealer skin/car icon selection, track grid, tuning/upgrade panels, options tabs and credits. All drawing emits portable physical pixel commands; no OpenGL code or dependency remains. The original `balks.bed` slices are drawn from `balks.dds` at the native PC positions. Their authored 640-wide frame repeats into widescreen margins with cropped end tiles; UVs stay inside each BED slice. Content and mouse targets share a centered, aspect preserving source canvas.
- `race_menu_gl.cpp` showroom → `frontend_scene.cpp`: authored startpoint transform, per-slot cameras/offset overrides, 20 second Catmull-Rom camera cycle, FOV conversion, garage/dealer/tuning slot selection and tuning dummy target. The host renderer draws geometry using the returned scene. Pause contexts disable this scene before any resource reads.
- `race_overlay_gl.hpp/.cpp` → `frontend_hud.hpp/.cpp`: countdown/go/finish/result/position/time/lap/battle/stunt/replay/music interface. Host supplies real gameplay state; result entries and event outcomes are never generated by UI.
- `data.cpp`, `menu_assets`, `car_config`, `font_assets`, `control_settings`, `menu_camera`, `race_ui` → `legacy_ui`: literal data and portable logic, namespace adapted to `ofo`; resource access adapted to `Resources::exists/paths`. `car_config` retains original equipment MaxSettings/upgrades resolution and provenance; gameplay must consume those settings separately.

## Integration

Core sources: `frontend.cpp`, `frontend_draw.cpp`, `frontend_scene.cpp`, `frontend_hud.cpp`, `legacy_ui/data.cpp`, `legacy_ui/menu_assets.cpp`, `legacy_ui/car_config.cpp`, `legacy_ui/font_assets.cpp`.

`Frontend(resources, profileDir, requestedGeometry)` starts at Start, loads one PLAYER profile plus controls, and exposes the v0.23 `MenuPage`, `choice`, `cars`, `track_slots`, current `row`, audio/options and action flags. `key(VK)` accepts the existing arrow/Enter/Escape virtual keys; Xbox A/B/d-pad should map to those same calls. `click(x,y,width,height)` is in physical pixels; `click_normalized` converts normalized pointer coordinates. `open_pause()` clears actions and preserves selection. Host consumes start/resume/restart/retire/replay/quit, then calls `clear_actions()`.

Use `selected_car_id()`, `choice.skin`, `selected_stage()`, `choice.automatic` for the actual race. `choice.track` is geometry, while `choice.stage`/`selected_stage()` is authored stage data. `car_upgrades(id)` returns persisted upgrade IDs. `car_configuration(resources,folder,ids).source_settings` contains resolved physics fields.

`ControlSettings::Action`: Gas, Reverse, Left, Right, Handbrake, Nitro, Camera, Recover, ShiftUp, ShiftDown, Brake. Held state is `down[keys[action]] || (secondary[action] && down[secondary[action]])`. `deadzone` and `sensitivity` configure Xbox steering.

`FrontendDraw` is Rect/Image/Text, physical pixel coordinates, ARGB color and image UV span. `frontend_draw.inc` can be included inside Renderer::Impl to reuse its quad/get/text methods. Eight original ABC fonts are emitted as Image glyphs, so the fallback Text route is only used if original font data are absent. `FrontendHud::commands(width,height,state)` uses the same list. Host keeps existing native gauges and minimap. The 3D authored route arrow needs the host geometry pipeline if real guidance is available.

## Verification

`tests/test_frontend.cpp DATA_ROOT [snapshots.json]` checks 16 cars and stats/skins/icons, 48 authored grid slots, 35 upgrades, complete Start→Profile→Main→SinglePlayer→Dealer→Transmission→Class→Track flow, purchase/profile/control persistence, pause resume/restart/retire confirmations, audio/controls/game tab return, explicit unsupported graphics settings, disabled pause showroom, garage camera transform and 18 screen command lists with full width bands and no obsolete atlas reference. HUD checks native countdown and five replay icons, supplied result rows, no fabricated standings and music bar.

`tests/test_frontend_visual.py snapshots.json DATA_ROOT output.png` composites the original DDS artwork/font glyphs into an 18 screen inspection sheet without requiring Direct3D. It verifies command placement/assets, not GPU shader or geometry rendering.

## Deliberate limits

The original UI's single PLAYER profile, career cash/upgrade model, authored event catalogs and explicit unsupported multiplayer/stunt messages are retained. This port does not implement missing career progression, stunt scoring, AI or multiplayer. Bloom/AO/PBR rows explicitly say NOT AVAILABLE in this D3D9Ex build, cannot enable those effects and do not restore old true settings. Direction-arrow availability requires a real authored route. Animated title smoke and 3D scene rendering are host renderer responsibilities via the scene inputs. Native GPU screenshot verification remains a host integration gate.
